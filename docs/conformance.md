# 符合性清单（Agent Hint v1.0 · DeerFlow 发送方）

`✅` 已验证（单测/集成/e2e 抓包） · `⚠️` 已实现但有已知偏差 · `—` 不适用 · `❌` 未实现

## 传输（W）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| W-01 hint 只在 `X-Agent-Hint` 头 | ✅ | e2e 全局断言：所有带 hint 的请求都只有该头 |
| W-02 请求 body 不含 hint 字段 | ✅ | e2e 断言 body 键集合无 hint |
| W-03 base64url、无 padding、UTF-8、合法 JSON | ✅ | 单测 + 抓包解码 |
| W-04 单头值、典型 < 1 KB、上限 4 KB | ✅ | 实测普通 hint < 400 B；构建器只发四块 |
| W-05 辅助请求无 hint | ✅ | 标题/摘要请求实测无头 |
| W-06 无会话身份的请求无 hint | ✅ | 仅当 task store 有 `TaskInfo` 时注入 |
| W-07 重试复用同一 hint | ✅ | `MODEL_LOGICAL` 在重试外层，值冻结；物理层按记录重建 |
| W-08 hint 无密钥/隐私 | ✅ | 只含会话 id、计数、枚举；trace 无内容 |

## 会话（S）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| S-01 `session_id` 稳定唯一 | ✅ | lead = `thread_id`；子代理 = `{thread}:{run}:{task}` |
| S-02 `parent_session_id` 只表示续接 | ✅ | 仅 branch 线程携带；子代理不声称父 |
| S-03 `call_index` 从 1 起、含本次、单调、重试不增 | ✅ | 事实表高水位；播种仅首次 |
| S-04 `epoch` 从 0 起、每次改写 +1、不回退 | ⚠️ | 以 `summary_text` 指纹为准；同间隙多次改写合并为 +1 |
| S-05 每个 hint 都有 `state` | ✅ | 构建器强制 |
| S-06 `start` 每会话一次；不确定用 `append` | ✅ | `start` 需“无历史 + 首请求未被接受” |
| S-07 并发/乱序下仍是请求级确定值 | ✅ | 事实按会话串行；值在逻辑调用打开时冻结 |
| S-08 子代理使用新 `session_id` | ✅ | 每次执行唯一；共享父 `thread_id` 也不会碰撞 |

## 优先级（P）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| P-01 每条普通请求带 `priority_control` | ✅ | `priority: omit` 时整块省略 |
| P-02 轮次开局 = 3/`user_waiting` | ✅ | 每个 lead task 的首条主线调用 + 人类来源 |
| P-03 续接 = 1/`critical_path` | ✅ | 同一 run 的后续调用、子代理、非人类来源 |
| P-04 level/reason 成对且一致 | ✅ | 构建器校验，单测覆盖非法组合 |
| P-05 manage / 辅助请求不带 priority | ✅ | manage 构建器不产生该块 |

## 缓存（C）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| C-01 单个 `ephemeral` 对象 | ✅ | 无 `range` 等额外键 |
| C-02 `ttl_s ∈ [60,3600]`；无样本 600 | ✅ | `clamp(round(interval*2))`，无样本 gap=300 |
| C-03 `msg_offset` = 逻辑输入条数，≥ 1 | ✅ | e2e 断言等于 wire `messages` 条数 |
| C-04 改写当轮抑制 | ✅ | `summary_text` 变化的那一轮 |
| C-05 模型/工具集签名变化当轮抑制 | ✅ | 签名 = model id + 排序工具名 |
| C-06 前缀 < 128 token 抑制 | ✅ | CJK 近似估算 |
| C-07 重启后签名未知且 `call_index > 1` 先抑制一轮 | ✅ | 事实表持久化签名；首次见到带历史会话时等价抑制 |
| C-08 manage / 辅助请求不带 cache | ✅ | 构建器分离 |

## 生命周期（L）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| L-01 `start` 触发正确 | ✅ | 首条被接受的普通请求 |
| L-02 `append` 覆盖其余主线请求 | ✅ | e2e |
| L-03 `pause` 在空闲 + 离开时发出且去重 | ⚠️ | “离开”用“同用户另一会话更晚被接受”推断（协议 V5 的推广）；单会话不发 |
| L-04 `resume` 在暂停/带历史会话再次使用前 | ✅ | e2e：resume 先于请求被接受 |
| L-05 `stop` 在会话结束时发出，不是每轮 | ✅ | 子代理结束；lead 归档/删除；每会话一次 |
| L-06 `compact` 在改写提交后、携带旧 epoch | ✅ | e2e：compact epoch 0 → 请求 epoch 1 |
| L-07 `state` 与 `edits[].type` 一致 | ✅ | 固定映射 + 校验器 |
| L-08 缺失触发源按画像降级 | ✅ | 见实现画像 |

## Manage（M）

| 编号 | 结论 | 备注 |
| --- | --- | --- |
| M-01 动词只出现在 manage 请求 | ✅ | 普通 hint 构建器拒绝生命周期动词 |
| M-02 `manage_request === true`（布尔） | ✅ | 单测 |
| M-03 恰好一个 edit、target=session | ✅ | 构建器强制 |
| M-04 body 为占位 `{model,messages:[],stream:false}` | ✅ | 单测 + e2e 抓包 |
| M-05 凭据与数据面一致或明确不同源 | ✅ | 复用模型实例凭据（仅内存）；覆盖端点时可单独给 key |
| M-06 只有四个动词 | ✅ | `ManageVerb` 字面量 |
| M-07 同会话串行 + 变更屏障 | ⚠️ | 串行 ✅；屏障为“有界等待”，超时放行 |
| M-08 未知结果进入隔离，不静默继续 | ⚠️ | 隔离并 WARN/状态可见，但请求照发且不带头（扩展钩子无法拒绝）；提供 clear-isolation 逃生路径 |
| M-09 只有 resume 可对明确瞬态重试 | ✅ | 408/429/5xx/网络；变更类不重试 |
| M-10 卸载后不再派发；退出时 stop 丢失已记录 | ✅ | 停机停止派发；线程持久，退出不发 stop |
